# SnapPhoto 📸 for Youdao Dictionary Pen

面向有道词典笔 X7 Pro（优先）的第三方 Falcon/HaaS MiniApp 相机应用。

**当前版本 0.9.3，已安装到 X7 Pro。** 修复退出后重新打开黑屏：每次启动重新注册相册模块，保留原厂库句柄。 已合并 PR #2，接通原厂 NPU，内置约 934 KiB 的 FFDNet INT8 模型。按快门从近期预览帧取图，保存原片后立即恢复拍摄，NPU 在独立后台队列处理；设置第六页选拍后降噪，第七页选退出后继续或暂停。真实多曝光 HDR 尚未接通，保持禁用。详见 [0.9.3 修复](docs/x7pro-0.9.3.md) 和 [0.9.2 功能记录](docs/x7pro-0.9.2.md) 和 [模型证据](docs/hdr-npu.md)。

## 词典笔操作

- 主界面参考原厂 AI 拍照：全屏取景、左上退出、右侧大快门、右上设置、右下相册。
- 在取景区域左右滑动切换拍照、录像、相册；拍摄中不切换模式，避免误操作。
- 倒计时、连拍、辅助线、方向和滤镜放在大字号的二级设置页。
- 相册点按预览照片／视频，右上“选择”后可多选删除、导入系统相册和导出；手机与词典笔在同一 Wi-Fi，扫码下载。凭据十分钟失效，退到后台停止服务。
- 方向选“自动”后由传感器联动界面和画面；录像中锁定方向。翻转自拍保留原有的全屏拍摄行为。

## 0.8.0 相册与成像

- 按系统相册 MiniApp 的五列缩略图、纵向滚动、点按预览和多选删除逻辑适配。视频可在笔上有声播放；网页导出支持 MP4 和本应用 MJPEG/PCM AVI 预览。
- 照片改用原厂扫描器支持的 `.JPG`，实际查询系统索引确认收录；旧 JPEG 可选中后“入系统相册”，不重新编码。
- 设置第五页提供自动暗光增强，以及速度／质量优先。默认速度优先，质量优先增加降噪；软件提亮不能补出未被传感器记录的细节。
- 方向旋转落实到输出像素；竖屏照片使用所选比例的完整分辨率。720p 横屏约 30 帧／秒、1080p 横屏约 24 帧／秒；本次加入 NEON 旋转后的 720p 竖屏约 25 帧／秒，随场景和滤镜变化。
- 本轮没有操作 ADB 持久化或重启设备。

## 0.7.0 独立高清录像

- 设置第四页 → 录像画质，提供省空间、720p、1080p。默认 720p；新增设置独立保存，不改变照片比例、自拍或方向偏好。

| 画质 | 横屏录像 | 竖屏录像 | 目标帧率 |
| --- | --- | --- | --- |
| 省空间 | 640×192 | 216×720 | 30 |
| 720p | 1280×720 | 720×1280 | 30 |
| 1080p | 1920×1080 | 1080×1920 | 24 |

- 录像从原有 3264×1836 NV12 图像独立裁剪、缩放；不再保存 UI 的小预览。高清预览单独保持 320×180 / 360×640，按选中画幅完整显示。三个有界缓冲和独立 JPEG 编码线程防止积压拖住取景，保存实际平均帧率，不复制帧凑数。数字变焦及滤镜仍应用于录像。
- 720p 第一轮实录约 30 帧/秒；1080p 原始编码实测约 25 帧/秒，应用界面录制约 22 帧/秒，现设目标 24。以上帧率为原图模式；黑白仍约 30 帧，720p 暖调本次实测约 15 帧。复杂场景、彩色滤镜、温度和其他程序负载会影响实际帧率；目标值不保证每段录像都达到。
- 视频仍为 MJPEG AVI，JPEG 质量参数 85，带 16 kHz 单声道 PCM，沿用采音启动、增益/限幅、麦克风占用处理和后台自动收尾。文件体积较大，本次场景约 720p 每分钟 110 MB、1080p 每分钟 170–180 MB，随内容变化。
- 开始录制要求至少 64 MB 可用空间，低于 32 MB 或单文件接近 1.75 GiB 时结束并保存，避免 AVI 超限；处于设置页时也处理自动停止。CLI 回归可用较小文件上限验证同一收尾路径，无需写满设备。
- 竖屏继续沿用中心竖向裁切语义，不改变照片尺寸；1080×1920 的竖向输出会对源画面的 1836 像素高度轻微放大。
- 硬件编码尝试：设备 MPP 版本 7d6c3974，与对应官方头文件核对后，H.264 初始化返回 -1；内核 `/proc/mpp_service/supports-device` 仅列 RKVDEC、RKJPEGD。没有将库文件存在当成硬编可用，没有修改内核、设备树或驱动，也未给出硬件永久不支持的结论。当前高清功能使用 CPU TurboJPEG。
- 实机回归工具：`python tools/verify-hd.py`。它检查六种画质/方向组合、音轨、完整解码、真实平均帧率、录像中禁止切画质、文件限额、后台保存和重开。执行前让其他相机退后台并保持设备亮屏。局域网下载测试继续按用户要求跳过。

## 0.6.0 预览、连续对焦与有声录像

- 预览直接采样 V4L2 映射中的所需行，缓存缩放坐标与 JPEG 编码器，只在拍照时复制一张完整 NV12。临时预览不再逐帧 fsync，保留最近 32 帧；关闭相机时清理自己的预览缓存。JS 以 33 毫秒轮询并丢弃重复图片，旧会话的返回值仍被丢弃。
- 同一设备亮屏、1416 MHz、未改频率策略的对照测试：横屏获取到的唯一预览从约 18.9 提升到 26.7 帧/秒；竖屏约 20.3 → 26.9；录像比例约 20.4 → 27.0。设置页显示的是 JS 预览更新频率，实机观察约 26–28 帧/秒；这不是屏幕扫描频率或逐帧呈现测量。息屏时系统降频，结果不应混用。
- 保留原厂 RKAIQ 连续 AF。拍照前只读查询 DW9714 的镜头位置，等待连续数帧稳定，通常约 220 毫秒，最多 1.4 秒；连拍只在第一张等待。超时仍可拍摄，不把“电机位置稳定”称为“对焦成功”。没有核实可用的跨进程 AF 控制接口，因此不提供点击对焦，也不直接写电机位置。退出时无需恢复镜头设置。
- 录像加入麦克风 PCM S16LE、16 kHz 单声道音轨；通过系统 `softvol_cap` 双通道采集后下混，复用其自动恢复话筒路由的钩子。采集后施加 4 倍（约 +12 dB）应用内增益并限幅，不改变其他应用的录音音量。AVI 同时交织 MJPEG 与 PCM，音频在线程中采集，索引动态有界扩展；停止和退后台关闭并释放麦克风。麦克风忙、音频溢出或写盘失败会报错并保留不完整文件。
- 前台通过固件已核实的 `global.Global.startAlwaysScreenOn()` 请求亮屏，后台和销毁配对 `stopAlwaysScreenOn()`，不修改用户的熄屏时长，避免录像过程中自动息屏降频。
- 不改变系统混音器、相机服务、驱动绑定、CPU 调频或持久 USB 解锁配置。视频仍为横屏 640×192 / 竖屏 216×720 的 MJPEG AVI，未引入 H.264 硬编或更高录像分辨率。
- 验证：`npm test`、`python tools/verify-performance.py`、`python tools/verify-profiles.py --skip-share`；后两项应在其他相机已退后台时运行。局域网下载测试按用户要求跳过。录制回归工具使用电脑的 ffmpeg/ffprobe；发行核验工具另需 Python pyelftools。

## 0.5.0 比例、滤镜与拍摄时间

- 横屏设置 → 照片比例：3.33:1（3264×979）、2.39:1（3264×1362）、2:1（3264×1632）、16:9（3264×1836）、4:3（2448×1836）、1:1（1836×1836）。竖屏不可调整，保留 216×720；切回横屏恢复所选比例。设置按原有方式持久保存。
- 预览显示完整照片裁切范围，按比例留黑边；录像维持横屏 640×192。相机会话始终采用已验证的 3264×1836 NV12，不为比例切换重新配置 ISP。4:3 是从该画幅居中裁切，不冒充传感器全幅 8MP。
- 原图、黑白、棕褐、暖调、冷调、复古、鲜艳、反色。保存照片采用轻度边缘保留降噪与有阈值、限幅的亮度锐化；需要缩放时使用双线性采样。预览保持轻量处理，原图/黑白走直接 YUV 编码，照片处理在独立线程执行；保存时界面显示状态并继续取景。这是 CPU 图像处理，未实现多帧超分或 NPU 推理。
- 新照片把该帧到达应用时的词典笔时钟写入 EXIF DateTimeOriginal、SubSecTimeOriginal、OffsetTimeOriginal，以及文件名。不是传感器硬件曝光时间；词典笔时钟不准时，照片时间也会不准，不自动修改系统时间。
- 局域网导出页显示原文件名、缩略图、拍摄时间、体积和剩余时间，支持 JSON 时间清单。下载原文件并保留带日期的原文件名与 EXIF，不压缩、不重编码。旧文件无拍摄时间时明确提示，不把修改时间冒充拍摄时间。
- 使用 `python tools/verify-profiles.py --skip-share` 在真实设备测试尺寸、滤镜、EXIF、竖屏、录像、下载、凭据、停止分享和相机重开。该工具创建测试媒体，通过自身协议配对关闭相机，不自动重绑内核驱动。

## 0.3.0 全屏自拍

- 打开相机并稳定握持一秒，记录起始姿势。上下倒转或屏幕朝上/朝下翻面并稳定约一秒后，自动隐藏全部按钮进入自拍；恢复到稳定的非翻转姿势后自动退出。恢复时不要求两个方向分类都与最初完全相同。
- 也可点取景页左下角“自拍”，或设置第三页“全屏自拍”手动进入。手动进入后下滑退出。
- 全屏中双击屏幕任意位置拍照，包括原快门按钮位置；两次可点不同位置。单击、长按和滑动不拍照，短时间连续多击只触发一轮拍摄。
- 保留现有倒计时及连拍设置；仅翻转不会自动拍照。下滑退出时恢复原先的拍照/录像模式。
- 设置第三页可关闭“翻转自拍”。方向传感器使用原厂 `gsensor.Gsensor` 的订阅和唤醒接口，只在相机前台配对启停；从输入设备只读当前方向，未修改系统持久配置。
- 设备的重力方向枚举不能可靠判断绕竖直轴的纯水平掉头，也不提供精确倾角；这种姿势请使用手动“自拍”入口。
- 33 项测试覆盖双击防重复、手势冲突、翻转稳定判定、非精确姿势恢复、传感器当前状态优先、订阅清理和已有相机流程。实机已验证全屏隐藏按钮、双击保存及下滑退出；自动进入获用户确认，修订后的自动恢复仍需手持复验。

## 实机能力和边界

照片按所选比例保存，最高 3264×2448 JPEG，正方形 2448×2448；预览与照片按同一比例居中裁切。竖屏将所选比例的完整照片旋转保存；相机传感器固定，方向设置适应持笔姿势。录像画质独立选择，最高为 1920×1080 / 1080×1920 MJPEG + PCM/AVI；帧率按实际录制数据写入。原厂相册索引在此前版本实机核验，保存目录正确本身不代表原厂相册已收录。

支持 1–3 倍数字变焦和八种滤镜（含原图）。连续对焦由已运行的系统服务管理；应用持续观察镜头位置和画面稳定性，不向电机写入焦距。0.9.2 快门改用近期原始预览帧，不再等待 AF 稳定；选帧不会无条件用抖动中的低清晰度画面覆盖较好帧。未实现点击对焦、系统 AF 锁定、光学变焦或真实 HDR。拍后 NPU 降噪在独立后台进程处理，预览与录像继续使用既有 ISP/CPU 路径。

设置保存在 `/userdisk/snapphoto/preferences.json`，照片/视频在 `/userdisk/Pictures`，均与 MiniApp 安装目录分开。未安装自动重装程序。设备端已启用原厂“关闭应用白名单卸载”开关，详情见 `docs/app-retention.md`；未修改白名单内容或原厂应用代码。

## 实机打包

先安装依赖并运行测试，再编译原生模块。编译目标为 aarch64 Linux/glibc 2.29，使用 Zig 0.14.1。最后用已授权连接的词典笔自带 QuickJS 编译字节码：

```text
npm ci
npm test
python native/build.py --zig <path-to-zig>
npm run build
python tools/build-x7pro.py
```

安装包在 `dist/SnapPhoto-X7Pro-0.9.3.amr`。`npm run build` 和 GitHub Actions 单独生成的前端预览包不含原生适配库，不能用于设备安装；实机请使用 `dist` 内的完整包。`tools/verify-profiles.py --skip-share` 和 `tools/verify-hd.py` 会在已授权设备实际拍照、录像并删除各自创建的媒体；需要 Pillow、ffmpeg/ffprobe。不要与其他相机测试同时执行。

仓库包含实机适配源码、公开 SDK 头文件、模型及授权、测试工具和不含私有数据的结构化验证记录。设备照片、截图、录音录像、固件运行库、日志、编译缓存与发行安装包保留在本地，不提交到 Git。

## 0.2.1 后台恢复修订

- 前台恢复时使用新的预览组件实例，不复用上一相机会话的图片变换状态。
- 丢弃后台前已经发出、恢复后才返回的预览帧。
- 串行处理相机打开与关闭；取消过期的前台初始化请求。
- 重新应用取景方向、变焦及滤镜。
- 已通过 24 项测试，以及原厂 AI 拍照切换回 SnapPhoto 后重新取景的实机检查。
- 实景上下方向尚待用户对准有方向标记的物体后确认；当前镜头画面缺少可辨方向的细节。
