# X7 Pro 0.8.1 修复说明

本轮按用户要求仅修改、构建和自动检查，不安装新版，不要求用户操作设备。真实方向、真实噪点观感及视频播放效果尚待后续实机确认。

## 方向

界面变换和取景像素原先在竖屏时同向各转 90°，叠加成为 180°。现在将界面旋转与相机像素旋转区分，相机取反向角度。自动、强制竖屏、重新连接相机和返回应用使用同一换算；录像中继续锁定方向。

## 相册

原先只创建最前面的 20 个图块，随后依赖滚动事件替换整批图块；当原生滚动范围或偏移失去同步，后面的内容就会空白。现在保留完整列表的稳定图块及滚动高度，只在当前窗口及相邻行挂载图片。滚动坐标兼容原生 `y` 和包装后的事件结构，加载与渲染共用窗口计算。选择操作不再重建滚动容器。

JPEG 照片先走系统 TurboJPEG 的 DCT 缩小解码，在工作线程里生成 160×160 的居中缩略图；仅视频或无法使用该路径的格式回退到 GStreamer。不为每张正常 JPEG 启动新进程。列表直接返回可用的缓存路径，刷新保留未变文件的缩略图；缓存使用新版本键及 256 项的上限，旧图滚回可重新生成，并非相册只能显示 256 项。

单个缩略图任务结束后，加载器重新查看当前窗口，快速滑动不会堆积旧窗口任务，也不会丢弃刚完成且仍有效的图片。返回预览页后的图库窗口与重新创建的滚动容器一起回到顶部。

## 暗光质量模式

原先 gamma 提亮会过度放大接近黑色的细微差异，预览还会先提亮再降噪。改为有界暗部曲线：黑色、高光端点保持不变，接近黑色处的斜率有限。质量模式在提亮前进行边缘保留的亮度与色度降噪，并适度压低极暗区域的彩色斑点。

照片、预览、录像及彩色滤镜共用 YUV 处理顺序；质量模式正在增强时跳过照片锐化，防止再次把颗粒锐化出来。算法不积累历史帧，避免因长时间融合产生拖影；质量模式仍比速度模式消耗更多 CPU，未对新版实机帧率作保证。

## 视频播放闪黑

播放中的图片控件沿用同一个 key，仅更新图片源；不再随每帧路径销毁并重建控件。解码器的临时帧复制为完整、原子发布且路径唯一的展示帧，最多保留最近 32 帧，避免原生界面异步读取时原文件已被删除。遇到不完整的新帧，保留上一张可用画面。停止播放时结束自身解码进程组。

本轮不调整系统驱动、启动脚本、ADB 持久化或录音路由。

## 验证边界

- JS 自动回归包含四向旋转换算、自动模式恢复、超过 20 项和 1001 项图库窗口、快速滚动任务重排、缓存、选择和视频控件稳定性。
- 本地 C 回归覆盖旋转像素、暗光滞回、曲线单调性、小尺寸及奇数尺寸内存边界、合成噪声与文字边界。
- 同一合成输入、同一提亮曲线下，对比质量与速度路径的亮度、色度噪声方差；仅为算法回归，不代表真实拍摄画质测量。
- 展示帧回归覆盖源文件删除、半写入 JPEG、路径唯一性与 32 帧缓存上限。
- ARM64 编译及前端构建成功不等同于真实设备验证。AMR 可使用已连接设备的原有 QuickJS 编译器生成字节码，该步骤只写本应用 `/tmp` 编译文件，不安装或启动新版。
