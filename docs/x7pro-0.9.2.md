# 0.9.2：快拍、内置模型和后台增强

已构建并安装到 X7 Pro / PenOS 4.34.0。原 [PR #2](https://github.com/xtawa/youdao-snapphoto/pull/2) 已合并；完整实机适配和新模型最初以安装包及源码压缩包交付，随后按用户要求连同 0.9.3 修复统一提交到仓库。

## 快门

0.9.1 的稳定等待过严，真实设备上会在按下快门后仍等待。0.9.2 移除了 X7 Pro 快门阶段的 AF 等待，复用持续采集的近期全分辨率 NV12 图。预览保留一张约 12MiB 的缓存，每隔最多约 150ms 更新；按快门转移缓存所有权，取帧最多接受 200ms 内的源帧，缺少缓存时取下一帧。拍摄时间记录实际源帧到达应用的时间。

原厂连续 AF 仍管理镜头，应用只读观察，不主动重启寻焦、锁焦或写电机。图像清晰度和手持运动仍由实际光学条件决定，不能保证任何时候按下都绝对清晰。

实机 5 次拍摄：取帧约 0.00–0.01ms，完整 JPEG 保存与测试通信 219–375ms；其中 2 次在 NPU 后台处理期间拍摄。快门不等待系统相册扫描或增强任务。系统相册扫描异步发起，索引状态不会伪装成已确认。

## 后台与保活

设置第六页：拍后降噪（关闭／自动／画质优先），NPU 已就绪。第七页：后台保活（退出后继续／退出后暂停）、任务进度。当前设备已设为自动降噪、退出后继续，保留其余照片比例、录像、暗光、方向等偏好。

原片先写入 `/userdisk/Pictures`，随后只把任务元数据写入 `/userdisk/snapphoto/jobs`。独立 helper 执行 NPU 降噪，生成另一张 `SNAP_AI_*.JPG`；原片不修改、不删除。队列最多 16 个待办，串行推理，最多保存 64 个已结束记录；工作进程降低 CPU 调度优先级，队列清空后退出，不安装开机常驻服务。

“退出后继续”让 worker 脱离 MiniApp 界面进程；“退出后暂停”在图块边界停止并保留待办，重新打开继续。异常终止后下次打开可恢复，最多尝试两次；源文件变更或删除会失败并保留原片。系统休眠可能暂停计算，关机或系统强制杀进程不在保活保证范围内。没有修改系统休眠策略。

静音播放实测会独占这台设备的默认扬声器，第二个播放器报设备忙，因此发行版不循环播放静音，也不改混音器。独立后台进程已实际验证在界面退出后完成 192 块 NPU 推理。

增强完成后，前台应用自动刷新并请求原厂相册扫描；若应用已退出，下次打开补做扫描。文件存在不等于系统索引已经确认。

## 模型与检查

内置 FFDNet INT8 956,463 字节及 MIT 授权，离线运行。12 层卷积在真实 RK3562 NPU；通过原厂 OEM RKNN 1.5.1b18 调用，驱动 0.9.1。详见 [模型和 ABI 记录](hdr-npu.md)。

- 100 项 JS 检查全部通过，覆盖快拍绕过 AF、异步相册不阻塞、后台入队、原有方向与相册等。
- 合成噪声图的真实 NPU 推理、参考输出差异、重叠块边界、取消与原片哈希保护通过。
- 3264×2448 / 192 块真实 NPU 处理与完整 JPEG 解码通过；前一轮独立进程约 20 秒、峰值 RSS 112MiB。后台低优先级和实际负载会增加耗时。
- 后台任务在 UI 进程退出后完成；关闭保活后的暂停、重新打开恢复通过。
- 原始 720p 录像音轨、帧数和完整 ffmpeg 解码通过；没有把静音保活写入录像。
- 实际安装包的字节码、原生分配节、模型和 helper 哈希与本地构建对应。

真实多曝光 HDR 仍未开放；参考融合算法不能替代曝光采集和配准。手持光学对焦和实际暗光主观画质仍需用户评估。没有重启设备、修改电源芯片、驱动、调频、系统音频路由或 ADB 持久化。
